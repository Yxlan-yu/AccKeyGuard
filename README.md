# 无障碍保活

KernelSU / Magisk 模块。定时检查「守护列表」里的无障碍服务，被系统关掉就自动补回来。

## 这个模块解决什么

不少机型会在一段时间后悄悄关闭无障碍服务（尤其是电池优化、权限回收、系统更新之后），
导致自动点击、屏幕朗读、辅助操作一类工具突然失效。本模块用一个常驻小进程盯着系统设置，
发现守护列表里的服务不在启用列表里就写回去，不需要用户手动进设置重新打开。

## 使用

1. 在 KernelSU Manager（或 Magisk）中安装模块，重启手机
2. 打开模块的 WebUI
3. 打开某个应用右侧的开关 → 该服务加入守护；若它当前没启用，会**同时被启用**

没有「保存」按钮：每次改动都会立刻写入配置（防抖 0.35 秒），退出页面不会丢失。

### 界面说明

- **顶部状态条**：只显示守护进程是否在运行（不可点）；设置从右上角齿轮进
- **搜索 / 筛选 / 排序**：按应用名、包名、服务名搜索；筛选「守护中 / 已启用 / 未启用」；筛选行右侧按钮可选按应用名、按应用名倒序、守护优先、待处理优先，选择会被记住
- **列表开关**：只表示「是否守护」，不表示无障碍开关本身
- **点整行**：打开详情，上面是「保活守护」，下面才是「手动停用 / 启用」
- **横幅**：只在需要你动手时出现 —— 守护进程没运行，或有守护项被系统关掉；按钮为「启动守护」/「立即恢复」

### 与旧版的区别

| 旧版 | 现在 |
|------|------|
| 勾选后要按「保存设置」 | 改动即时保存 |
| 每次勾选都弹「是否顺带启用」 | 直接启用，不再打断 |
| 状态徽标也能点（语义混乱） | 状态只显示，设置只从齿轮进 |
| 每次刷新按状态重排，列表会跳 | 排序由你选择并记住，只原地更新状态 |
| 守护没运行也只有一个红点 | 横幅给出「启动守护」按钮 |
| 同步散落在动作按钮和 WebUI 两处 | 只在 WebUI 保留「立即恢复」，且有待恢复项才出现 |
| 详情/日志整页切换 | 底部弹层，关闭即回原位 |

## 配置

配置保存在 KernelSU module config（`/data/adb/ksu/module_configs/acckeyguard`）：

| Key | 说明 | 默认 |
|-----|------|------|
| `enabled_services` | 守护列表，冒号分隔的完整组件名 | 首次运行接管当前已启用项 |
| `check_interval` | 检查间隔（秒），5–300 | `20` |
| `theme` | `auto` / `light` / `dark` | `auto` |

检查间隔在 WebUI「设置」里改，守护进程每轮重新读取，不需要重启。

## 恢复被关掉的服务

守护进程每轮（默认 20 秒）都会自动补回。想立刻补回时，用 WebUI 横幅上的「立即恢复」，
或设置里同样只在有服务被关掉时才出现的「恢复 N 个被关掉的服务」。
模块没有 KSU 动作按钮，所有操作都在 WebUI 里完成。

## 日志

`/data/adb/modules/acckeyguard/data/accd.log`，WebUI「设置 → 查看守护日志」可看最新 80 行并一键复制。
日志超过 256KB 会自动截断为最后 128KB，长期使用不会无限增长。

## 说明

- 取消守护**不会**停用无障碍服务，只是不再自动恢复
- 守护只做「补回」，不会替用户启用从未加入守护列表的服务
- 模块不改动系统分区文件，卸载后无障碍设置保持原样
